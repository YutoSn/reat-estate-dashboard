# 住まい選びダッシュボード

今1歳未満の子どもがいる家族が、**これから家を建てる場所**を公的統計から見極めるためのアプリ。

「今の便利さ」ではなく「子どもが学校に通う頃どうなっているか」で判断できるように、
子どもの成長タイムラインを軸にデータを並べている。

対象は**岩手・宮城・山形・茨城・埼玉・千葉・東京・神奈川の8都県／402市区町村**。

---

## 何ができるか

| 画面 | 用途 |
|---|---|
| **探す** | 5つの観点の重みを自分で決めて、市区町村をランキング表示する |
| **詳しく見る** | 1市区町村の全指標、子どもの学齢期ごとの同年代人口推計、価格推移、地区別単価 |
| **比べる** | 最大6市区町村をレーダーチャートと表で横並び比較 |
| **災害リスク** | 洪水・土砂・津波の想定区域と地形分類を地図に重ねる |

### 子どもの成長タイムライン

2025年生まれの子を起点に、住まい選びで効いてくる時期を定義している。

| ステージ | 西暦 | 年齢 |
|---|---|---|
| 保育園・こども園 | 2025〜2030年 | 0〜5歳 |
| 小学校 | 2031〜2036年 | 6〜11歳 |
| 中学校 | 2037〜2039年 | 12〜14歳 |

起点は `config.py` の `CHILD_BIRTH_YEAR` で変更できる。

## セットアップ

### 必要なもの

`.env` に2つのAPIキーを置く。

```
E_STAT_APP_ID=<e-Stat の appId>
REAL_ESTATE_LIBRARY_API_KEY=<不動産情報ライブラリのキー>
```

- e-Stat: https://www.e-stat.go.jp/api/ （無料・登録制）
- 不動産情報ライブラリ: https://www.reinfolib.mlit.go.jp/ （無料・登録制）

### インストールと起動

```bash
pip install -r requirements.txt
cd frontend && npm install && npm run build && cd ..
uvicorn server:app --reload
```

http://127.0.0.1:8000 で開く。

フロントを触るときは Vite の開発サーバーを使う（`/api` は8000番にプロキシされる）。

```bash
cd frontend && npm run dev
```

### データの取得

```bash
python populate.py            # 全部（不動産取引が15〜30分かかる）
python populate.py --stats    # e-Stat の統計だけ（約3分）
python populate.py --prices   # 不動産取引だけ
python populate.py --scores   # 取得済みデータからスコアだけ再計算
```

> **取得中は uvicorn を止めること。**
> DuckDB は書き込みを1プロセスしか許さないため、サーバーが起動したままだと
> `File is already open` で失敗する（その旨のメッセージが出る）。
> サーバー側は読み取り専用で開いているので、参照は複数ワーカーでも競合しない。

## 集計の考え方

ここが結果を大きく左右するので、意図を明記しておく。

### 1. 土地の単価は「宅地(土地)」だけで計算する

国交省の取引データには4つの種別が混在している。

| 種別 | 件数 | ㎡単価の提供 |
|---|---:|---|
| 宅地(土地と建物) | 874,888 | なし |
| 中古マンション等 | 760,211 | なし |
| **宅地(土地)** | **539,839** | **あり（全件）** |
| 農地・林地 | 107,696 | なし |

`取引価格 ÷ 面積` を全種別で計算すると、マンションの専有面積単価と土地単価が
合算されて**地価として意味をなさない**。そこで

- 種別 = `宅地(土地)` かつ 地域区分 = `住宅地` に限定
- 国交省が直接提供する `UnitPrice`（㎡単価）を使う
- 統計量は平均でなく**中央値**（170億円のような極端な取引で平均が跳ねるため）

戸建て価格（土地と建物）とマンション価格は、別系列として並記している。

### 2. 面積のマスク値を除外する

国交省APIは一定面積以上を `2000` `5000` `8888` `9999` に丸めて返す（全体の1.9%、42,738件）。
これを面積として使うと単価が潰れるため、`area_is_masked` フラグを立てて単価系の集計から外す。

### 3. 取引が少ない自治体には単価を出さない

直近3年で住宅地の土地取引が**10件未満**の自治体は単価を空欄にする。
千代田区のように純粋な土地取引がほぼ無い地域では、数件の中央値が実勢から大きくずれるため。

### 4. 集計途中の年をグラフから外す

取引データは四半期ごとに増えるので、進行中の年は件数が数分の一しかない。
そのまま折れ線にすると年末に向けて急落して見えるため、`is_partial` を付けてグラフから除いている。

### 5. 密度に直してから比べる

「保育所数」「医師数」の絶対数は人口規模に引きずられるので、必ず人口や対象年齢の
子ども数で割ってから比較する。

## 子どもの同年代人口の推計（出生コホート法）

「小学校に上がる2031年、この街の6〜11歳は何人か」を推計している。

### 手順

1. **土台は出生数**。年次で2023年まで取れる（国勢調査の年齢別人口は5年間隔・2020年が最新）。
2. **定着率**を国勢調査の実績から求める。

   ```
   定着率 = 実際の6〜11歳人口 ÷ その学年が生まれた6年間の出生数合計
   ```

3. 対象年に該当する出生コホートに定着率を掛ける。
   出生数が未公表の年（2024年以降）は直近3年平均で補う。

### 定着率の読み方

| 値 | 意味 |
|---|---|
| **1.0超** | 生まれた数より多い＝**子育て世帯が転入してくる街** |
| 0.9〜1.0 | ほぼ横ばい |
| **0.9未満** | 生まれた数より少ない＝就学前後に**転出がある街** |

実例（2020年国勢調査ベース）:

| 市区町村 | 保育園期 | 小学校期 | 中学校期 |
|---|---:|---:|---:|
| 世田谷区 | 0.98 | 1.00 | 1.03 |
| 川口市 | 1.04 | 0.98 | 0.95 |
| 盛岡市 | 0.93 | 0.95 | 0.97 |
| 市川市 | 0.95 | 0.85 | 0.79 |

### なぜ最新の調査年だけを使うか

過去の調査年を平均すると、2015年国勢調査のように不詳が多く値が沈む年に引きずられる。
市川市では実勢0.95に対し**0.79まで下がった**。将来を見るための率なので、
最新調査年の実績をそのまま使い、根拠の年を画面に併記している。

## スコアリング

### 正規化

対象402市区町村の中での**パーセンタイル順位**を0〜100に変換する。
絶対値を線形に伸縮すると外れ値ひとつで全体が潰れるため。

**スコアは「この8都県の中での相対的な位置」であり、絶対評価ではない。**

### 5つの観点

| 観点 | 既定の重み | 構成指標 |
|---|---:|---|
| **子育て・教育** | 30% | 保育所密度、小学校教員1人あたり児童数（少ないほど良）、子ども1人あたり児童福祉費、児童福祉施設密度 |
| **将来の見通し** | 25% | 2050年までの人口推計、年少人口の10年変化、社会増減、財政力指数 |
| **医療アクセス** | 15% | 医師・診療所・病院の人口あたり密度 |
| **住環境** | 15% | 一戸建比率、図書館密度 |
| **手が届きやすさ** | 15% | 住宅地の実取引㎡単価（安いほど良） |

重みは画面のスライダーで変更でき、総合点がその場で再計算される。
**単一の「正解の総合点」は用意していない**。何を重視するかは家庭ごとに違うため。

## 既知の制約

事実として押さえておくべき点。

### 更新が止まっている統計

e-Stat側で更新が停止しており、**スコアには使っていない**（画面には観測年つきの参考値として表示）。

| 指標 | 最新年 |
|---|---|
| 刑法犯認知件数 | 2008年 |
| 交通事故発生件数 | 2009年 |

治安・交通安全を数値でスコア化できていないのはこのため。
安全面は「災害リスク」タブの地図で候補地そのものを確認してほしい。

### 更新頻度の違い

年齢別人口（0〜5歳など）は国勢調査由来のため**2020年が最新**で、5年ごとにしか更新されない。
一方で出生数は2023年、学校数は2024年まである。画面では**全ての指標に観測年を併記**している。

### 小規模自治体の density バイアス

人口が少ない町村は「子ども1000人あたりの保育所数」が構造的に高く出る。
一方で医師密度や将来人口では不利になりやすい。ランキングに**人口規模フィルタ**を用意しているので併用する。

例: 美里町（埼玉・人口10,685人）は保育所密度10.1（川口市4.7）だが、
医師密度2.81（川口市15.3）、2050年人口 -20%。

### 政令市の扱い

政令指定都市は「市」と「区」の両方がe-Statから返るが、**区の粒度を採用**している
（横浜市青葉区と鶴見区では性格が大きく違うため）。
「特別区部」は23区の合計であって自治体ではないので除外した。

### その他

- 通勤時間・交通利便性のデータは含まれていない（昼夜間人口比率が間接的な手がかり）
- 待機児童数は市区町村単位で継続的に取れる公的統計が無く、保育所密度で代替している
- スコアは公的統計の引用であり、特定の物件や投資判断を推奨するものではない

## 構成

```
config.py                  対象都県、子どもの成長タイムライン
populate.py                データ取得〜スコア算出の一括実行
server.py                  FastAPI（API + ビルド済みフロントの配信）
src/
  indicators.py            e-Stat 45指標のカタログ（統計表ID・カテゴリコード）
  fetchers/
    estat_api.py           e-Stat 汎用フェッチャ（ページネーション対応）
    real_estate_api.py     国交省 XIT001 の取得と正規化
  db/duckdb_manager.py     DuckDB のスキーマと集計クエリ
  analysis/
    metrics.py             派生指標の算出、出生コホート法による推計
    scoring.py             パーセンタイル正規化と観点別スコア
frontend/
  index.html / main.js / style.css
```

### テーブル

| テーブル | 行数 | 内容 |
|---|---:|---|
| `municipalities` | 402 | 市区町村マスタ |
| `municipality_stats` | 315,556 | 統計値（long形式: code, year, indicator, value） |
| `land_prices` | 2,282,634 | 不動産取引（種別・地域区分・㎡単価を保持） |
| `municipality_scores` | 18,642 | スコアと派生指標 |

統計値をlong形式で持っているので、`src/indicators.py` に1行足して
`python populate.py --stats` を回せば指標を追加できる（スキーマ変更は不要）。

## 主なAPI

| エンドポイント | 内容 |
|---|---|
| `GET /api/meta` | 指標カタログ、観点の定義、成長タイムライン |
| `GET /api/prefectures` / `cities/{pref}` / `districts/{city}` | 選択肢 |
| `GET /api/municipality/{code}` | 詳細一式（スコア、推計、価格・人口推移） |
| `GET /api/municipality/{code}/districts` | 地区別の単価ランキング |
| `GET /api/ranking?pref_code=&limit=` | スコア一覧（重み付けはフロントで再計算） |
| `GET /api/compare?codes=a,b,c` | 複数市区町村の比較 |
| `GET /api/tiles/{z}/{x}/{y}` | 国交省地価タイルのプロキシ |
