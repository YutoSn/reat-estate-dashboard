# 住まい選びダッシュボード

今1歳未満の子どもがいる家族が、**これから家を建てる場所**を公的統計から見極めるためのアプリ。

「今の便利さ」ではなく「子どもが学校に通う頃どうなっているか」で判断できるように、
子どもの成長タイムラインを軸にデータを並べている。

対象は**岩手・宮城・山形・茨城・埼玉・千葉・東京・神奈川の8都県／402市区町村**。

---

## 何ができるか

| 画面 | 用途 |
|---|---|
| **探す** | 6つの観点の重みを自分で決めて、市区町村をランキング表示する。世帯年収を入れると予算で届く街が上に来る |
| **詳しく見る・比べる** | 市区町村を最大6件まで選ぶ。2件以上で比較表とレーダーが出て、選んだ1件の詳細（全指標、スコアの内訳、学齢期ごとの同年代人口推計、価格推移、地区別単価）を下に表示する |
| **災害リスク** | 洪水・土砂・津波の想定区域と地形分類を地図に重ねる |

### 子どもの成長タイムライン

2025年生まれの子を起点に、住まい選びで効いてくる時期を定義している。

| ステージ | 西暦 | 年齢 |
|---|---|---|
| 保育園・こども園 | 2025〜2030年 | 0〜5歳 |
| 小学校 | 2031〜2036年 | 6〜11歳 |
| 中学校 | 2037〜2039年 | 12〜14歳 |

起点は `config.py` の `CHILD_BIRTH_YEAR` で変更できる。

## セットアップ

### 必要なもの

`.env` に2つのAPIキーを置く。

```
E_STAT_APP_ID=<e-Stat の appId>
REAL_ESTATE_LIBRARY_API_KEY=<不動産情報ライブラリのキー>
```

- e-Stat: https://www.e-stat.go.jp/api/ （無料・登録制）
- 不動産情報ライブラリ: https://www.reinfolib.mlit.go.jp/ （無料・登録制）

### インストールと起動

```bash
pip install -r requirements.txt
cd frontend && npm install && npm run build && cd ..
uvicorn server:app --reload
```

http://127.0.0.1:8000 で開く。

フロントを触るときは Vite の開発サーバーを使う（`/api` は8000番にプロキシされる）。

```bash
cd frontend && npm run dev
```

### データの取得

```bash
python populate.py            # 全部（不動産取引が15〜30分かかる）
python populate.py --stats    # e-Stat の統計だけ（約3分）
python populate.py --prices   # 不動産取引だけ
python populate.py --medical  # 医療機関だけ（約25分）
python populate.py --scores   # 取得済みデータからスコアだけ再計算
```

> **取得中は uvicorn を止めること。**
> DuckDB は書き込みを1プロセスしか許さないため、サーバーが起動したままだと
> `File is already open` で失敗する（その旨のメッセージが出る）。
> サーバー側は読み取り専用で開いているので、参照は複数ワーカーでも競合しない。

## 集計の考え方

ここが結果を大きく左右するので、意図を明記しておく。

### 1. 土地の単価は「宅地(土地)」だけで計算する

国交省の取引データには4つの種別が混在している。

| 種別 | 件数 | ㎡単価の提供 |
|---|---:|---|
| 宅地(土地と建物) | 874,888 | なし |
| 中古マンション等 | 760,211 | なし |
| **宅地(土地)** | **539,839** | **あり（全件）** |
| 農地・林地 | 107,696 | なし |

`取引価格 ÷ 面積` を全種別で計算すると、マンションの専有面積単価と土地単価が
合算されて**地価として意味をなさない**。そこで

- 種別 = `宅地(土地)` かつ 地域区分 = `住宅地` に限定
- 国交省が直接提供する `UnitPrice`（㎡単価）を使う
- 統計量は平均でなく**中央値**（170億円のような極端な取引で平均が跳ねるため）

戸建て価格（土地と建物）とマンション価格は、別系列として並記している。

### 2. 面積のマスク値を除外する

国交省APIは一定面積以上を `2000` `5000` `8888` `9999` に丸めて返す（全体の1.9%、42,738件）。
これを面積として使うと単価が潰れるため、`area_is_masked` フラグを立てて単価系の集計から外す。

### 3. 取引が少ない自治体には単価を出さない

直近3年で住宅地の土地取引が**10件未満**の自治体は単価を空欄にする。
千代田区のように純粋な土地取引がほぼ無い地域では、数件の中央値が実勢から大きくずれるため。

### 4. 集計途中の年をグラフから外す

取引データは四半期ごとに増えるので、進行中の年は件数が数分の一しかない。
そのまま折れ線にすると年末に向けて急落して見えるため、`is_partial` を付けてグラフから除いている。

### 5. 医療は市境をまたいで数える

医師数を自市内の人口で割ると、「自分の市には少ないが、隣の市の病院に15分で行ける」
という実態が落ちる。逆に大学病院を1つ抱える小さな町は、その町の住民だけで割られて
極端に高く出る（矢巾町は岩手医大があるため自市内 215人/万人 だが、実際には
岩手県全体を診ている）。

そこで**用途で使い分ける**。

| 指標 | 範囲 | 分母 | 理由 |
|---|---|---|---|
| 診療所の密度 | 自市内 | 総人口 | かかりつけ医は日常的に通うので近さが効く |
| 医師の密度 | 15km圏 | 総人口 | 専門受診は車で行く |
| 病院の密度 | 15km圏 | 総人口 | 入院・救急は車で行く |
| **小児科の密度** | 15km圏 | **15歳未満人口** | 乳幼児期にいちばん通う先 |
| **産科の密度** | 15km圏 | 総人口 | 第二子以降の受け皿 |

圏内は供給も需要も合計してから割る。

```
圏内密度 = Σ(15km圏内の医師数) ÷ Σ(15km圏内の人口) × 10000
```

**小児科だけ分母を子どもの数にしている。** 総人口で割ると、高齢者が多く
子どもが少ない街ほど「手厚い」と出てしまう。診てもらう相手は子どもなので、
分母も子どもでなければ意味がない。

効果（15km圏）:

| 市区町村 | 自市内 | 15km圏 | |
|---|---:|---:|---|
| 河内町（茨城） | 0.0 | 25.1 | 医師ゼロだが圏内にはある |
| 南房総市（千葉） | 7.3 | 56.2 | 隣の館山市に集中 |
| 江戸川区（東京） | 13.6 | 41.8 | 区内は少ないが周りが厚い |
| 矢巾町（岩手） | 215.6 | 43.4 | 岩手医大1つによる過大を補正 |
| 千代田区（東京） | 281.1 | 38.7 | 分母が居住人口なので過大 |

半径は `config.py` の `CATCHMENT_RADIUS_KM`。距離は代表点どうしの直線距離で、
道路網も山や川も見ていない（都心アクセスと同じ但し書き）。

### 対象8都県の外は数えられない

県境の自治体は、隣の県の医療機関を数えられないぶん過小評価になる。
そこで隣接9県（青森・秋田・福島・栃木・群馬・新潟・山梨・長野・静岡）の
**代表点と、人口・医師数・病院数だけ**を持っている。e-Stat は指標ごとに全国を
返すので、追加のリクエストは発生しない（保存する行を増やすだけ）。

統計が未取得の自治体が圏内にあるときは、その数を画面に出している。
黙って数字だけ出すと、県境の自治体だけ理由なく低く見えるため。

> **`data/municipality_geo.csv` に隣接県の代表点は入っているが、統計は
> `populate.py --stats` を実行するまで入らない。** 未実行のあいだ、県境の
> 29自治体は圏内が削られたままになる（画面には「うち◯自治体は統計未取得」と出る）。

### 6. 小児科は「小児歯科」と混ぜない

小児科の数は、施設単位の医療機関データ（不動産情報ライブラリ XKT010、
国土数値情報 P04）の**診療科目の文字列**から数えている。この文字列は
施設ごとに書き方がまったく揃っていない。

```
診療所   内科　小児科　アレルギー科      … 正式名
病院     内　外　小　泌　眼　耳　整      … 一文字略称
歯科     歯科　小児歯科　矯正歯科        … 小児"歯科"
```

**部分一致で数えると事故る。** 実データ10,983施設では

| 表記 | 件数 |
|---|---:|
| 小児歯科 | 1,882 |
| 小児科 | 862 |
| 小歯（＝小児歯科の略） | 745 |
| 小（＝小児科の略） | 310 |

で、`"小児" in text` のような判定だと**2.40倍に水増しされる**。
そこでトークンに分割したうえで**完全一致**でのみ判定する
（`src/analysis/specialties.py`）。

小児科と数えるのは `小児科` `小` `小児` `小児内科` のみ。
小児外科・小児皮膚科・小児神経内科などの専門科は、乳幼児を日常的に
診てもらう先ではないので含めない。

さらに**歯科診療所は種別で先に落とす**。一部の歯科医院は「小児歯科」を
`歯科　小児` のように分けて書くため、トークン単位で見ても単独の `小児` が
現れるため。実データでは単独 `小児` を持つ141施設のうち70施設が歯科だった。

検証結果（10,983施設）:

| 項目 | 結果 |
|---|---|
| 歯科診療所の誤検出 | **0件** |
| 小児歯科を持つ施設のうち小児科判定 | 8件（帝京大学病院・国立成育医療研究センター等、実際に両方を持つ大病院で正しい） |
| 名称は小児科だが判定されず | 6件（元データの科目欄が未記載。全体の0.05%） |

判定ロジックは `tests/test_specialties.py` に実データの表記ゆれをそのまま
ケース化してある（pytest が無くても `python tests/test_specialties.py` で走る）。

対象8都県とその圏内で取得した **66,483施設のうち、小児科 8,536・産科 1,655**。

### 圏内の母数が小さすぎる自治体には密度を出さない

七ヶ宿町の15km圏には子どもが90人しかおらず、小児科が1施設あるかないかで
「子ども1万人あたり」の値が100以上動く。桁の合わない数字を順位付けに混ぜると、
離島や山間の町がそれだけで上位を独占してしまう。

そこで圏内の母数に下限を設けた（`SupplySpec.min_demand`）。

| 指標 | 下限 |
|---|---:|
| 小児科の密度 | 圏内の15歳未満人口 1,000人 |
| 医師・病院・産科の密度 | 圏内の総人口 5,000人 |

これで402自治体のうち15自治体（伊豆諸島・小笠原と、七ヶ宿町・西和賀町など
山間部）が小児科密度の対象外になる。**0点にはせず、その観点の平均から外す**
（データが無いことと、悪いことは違うため）。

### 7. 密度に直してから比べる

「保育所数」「医師数」の絶対数は人口規模に引きずられるので、必ず人口や対象年齢の
子ども数で割ってから比較する。

人口密度だけは総面積ではなく**可住地面積**で割る。総面積で割ると、
市域の大半が山地の市（宮古市など）が実際の街の密度より不当に低く出るため。

## 都心へのアクセスをどう測っているか

市区町村の代表点から、**東京駅までの直線距離**と、**最寄りの広域中心までの直線距離**を出している。

| ハブ | 対応する圏域 |
|---|---|
| 東京駅 | 東京・埼玉南部・千葉西部・神奈川北東部 |
| 横浜駅 / 大宮駅 / 千葉駅 / 水戸駅 | 各都県の中心 |
| 仙台駅 / 盛岡駅 / 山形駅 | 東北3県の中心 |

東京駅までの距離だけだと、岩手・宮城・山形の402市区町村がすべて最下位に張り付いて
県内での差が出ない。「盛岡に通える町か」は岩手に住む人にとっての利便性そのものなので、
最寄りハブまでの距離を別の指標として並べている。

### 代表点の決め方

e-Stat も不動産情報ライブラリも座標を返さないため、住所オープンデータの
町丁目の座標から市区町村ごとの代表点を求めている。**平均ではなく中央値**を使う。
町丁目の点は市街地に密に、山林側に疎に分布するので、中央値を取ると
「実際に人が住んでいるあたり」に寄る。行政区域の幾何重心だと、
面積の大半が山地の市で人の住まない山の中を指してしまう。

再生成は次のコマンド（約50MBの住所データを取得するので `populate.py` からは呼ばない）。

```bash
python scripts/build_municipality_geo.py
```

## 世帯年収から予算を出す

世帯年収を入れると、「手が届きやすさ」の評価が**価格の安さ**から
**その予算で届くかどうか**に切り替わる。

### 予算

```
借入可能額 = 年収 × 返済負担率 ÷ 12 を月返済とする元利均等ローンの現価
             （金利1.5% / 35年）
予算       = 自己資金 + 借入可能額
```

返済負担率（初期値25%）と自己資金、建物＋諸費用の想定（初期値2,500万円）は画面で変えられる。

### 必要額

```
必要額 = 住宅地の実取引㎡単価 × 土地面積 + 建物＋諸費用
```

土地面積は既定でその自治体の**実際の取引面積の中央値**を使う。
ただし取引の少ない自治体では中央値が800㎡といった値になるため 100〜300㎡ で挟む。
固定値（120 / 150 / 200㎡）に切り替えることもできる。

### 予算比を点数にするときの考え方

安ければ安いほど高得点、にはしていない。

| 予算 ÷ 必要額 | 点数 |
|---|---:|
| 0.6以下 | 0 |
| 1.0（ぎりぎり届く） | 80 |
| 1.5以上 | 100（頭打ち） |

**予算に収まった時点で資金面の条件は満たしており、そこから先は子育て環境や
利便性で選ぶべき**だからだ。頭打ちにしておくと、届く街どうしの順位は
他の観点で決まる。届かない側だけを強く減点している。

年収700万円・頭金なしで試すと、上位が千代田区・中央区から
千葉市中央区・つくば市・青梅市に入れ替わる。年収2,000万円にすると都心が戻ってくる。

## 子どもの同年代人口の推計（出生コホート法）

「小学校に上がる2031年、この街の6〜11歳は何人か」を推計している。

### 手順

1. **土台は出生数**。年次で2023年まで取れる（国勢調査の年齢別人口は5年間隔・2020年が最新）。
2. **定着率**を国勢調査の実績から求める。

   ```
   定着率 = 実際の6〜11歳人口 ÷ その学年が生まれた6年間の出生数合計
   ```

3. 対象年に該当する出生コホートに定着率を掛ける。
   出生数が未公表の年（2024年以降）は直近3年平均で補う。

### 定着率の読み方

| 値 | 意味 |
|---|---|
| **1.0超** | 生まれた数より多い＝**子育て世帯が転入してくる街** |
| 0.9〜1.0 | ほぼ横ばい |
| **0.9未満** | 生まれた数より少ない＝就学前後に**転出がある街** |

実例（2020年国勢調査ベース）:

| 市区町村 | 保育園期 | 小学校期 | 中学校期 |
|---|---:|---:|---:|
| 世田谷区 | 0.98 | 1.00 | 1.03 |
| 川口市 | 1.04 | 0.98 | 0.95 |
| 盛岡市 | 0.93 | 0.95 | 0.97 |
| 市川市 | 0.95 | 0.85 | 0.79 |

### なぜ最新の調査年だけを使うか

過去の調査年を平均すると、2015年国勢調査のように不詳が多く値が沈む年に引きずられる。
市川市では実勢0.95に対し**0.79まで下がった**。将来を見るための率なので、
最新調査年の実績をそのまま使い、根拠の年を画面に併記している。

## スコアリング

### 正規化

対象402市区町村の中での**パーセンタイル順位**を0〜100に変換する。
絶対値を線形に伸縮すると外れ値ひとつで全体が潰れるため。

**スコアは「この8都県の中での相対的な位置」であり、絶対評価ではない。**

### 6つの観点

| 観点 | 既定の重み | 構成指標 |
|---|---:|---|
| **子育て・教育** | 25% | 保育所密度、小学校教員1人あたり児童数（少ないほど良）、子ども1人あたり児童福祉費、児童福祉施設密度 |
| **将来の見通し** | 20% | 2050年までの人口推計、年少人口の10年変化、社会増減、財政力指数 |
| **利便性** | 15% | 東京駅までの距離、最寄り広域中心までの距離（いずれも少ないほど良）、可住地人口密度 |
| **医療アクセス** | 15% | 診療所は自市内の密度、医師・病院・小児科・産科は15km圏の密度。小児科だけ分母が15歳未満人口 |
| **手が届きやすさ** | 15% | 住宅地の実取引㎡単価（安いほど良）／世帯年収を入れると予算適合度に切り替わる |
| **住環境** | 10% | 一戸建比率、図書館密度 |

重みは画面のスライダーで変更でき、総合点がその場で再計算される。
**単一の「正解の総合点」は用意していない**。何を重視するかは家庭ごとに違うため。

利便性と住環境は正面からぶつかる（都心に近いほど戸建て比率は下がる）。
スライダーはこのトレードオフを家庭ごとに決めるためにある。

指標が取れなかった場合、その指標は観点の平均から**外れる**（0点にはしない）。
データが無いことと、悪いことは違うため。

### 弱点補正（総合点は単純な加重平均ではない）

加重平均だけで並べると、5観点が80点でも1観点が20点の街が、全観点60点台の街より
上に来る。家を建てて15年住む場所としては、突出した強みより**決定的に困る点が
無いこと**の方が効くので、いちばん低い観点が基準点を下回っているぶんだけ差し引く。

```
総合点 = 観点の加重平均 − max(0, 基準点 − 最低の観点) × 0.5
```

基準点の既定は50点。閾値をまたいだ瞬間に順位が飛ぶのを避けるため、
「下回った点数 × 係数」の連続的な減点にしている（49点と51点の街が地続きになる）。

**重み0の観点は弱点判定から外れる。** スライダーを0にするのは
「その観点は見ない」という意思表示なので、低くても減点しない。

効果（既定の重み）:

| 市区町村 | 加重平均 | 最低の観点 | 総合 | 順位の変化 |
|---|---:|---|---:|---|
| 文京区 | 66.8 | 価格 1点 | 42.2 | 4位 → 84位 |
| 塩竈市 | 57.0 | 住環境 48点 | 56.0 | 52位 → 8位 |
| 天童市 | 59.0 | 利便性 47点 | 58.0 | 38位 → 6位 |

画面では、減点の原因になった観点のセルに印が付き、総合点の下に
「平均◯◯ − 弱点◯◯」と出る。

### 「最低でも50点以上」は該当ゼロ

**全6観点が50点以上の市区町村は1件も無い**（最良は塩竈市の48点）。
観点どうしが構造的にぶつかるためで、都心に近いほど戸建て比率と価格の点は下がる。
「全観点で上位半分」は成立しない条件だと分かった上で基準点を選べるよう、
足切り（減点ではなく除外）を選ぶと各基準点で何件残るかを画面に出している。

| 基準点 | 残る市区町村 |
|---:|---:|
| 40点 | 19件 |
| 45点 | 7件 |
| 50点 | 0件 |

### 計算式は画面で開ける

「探す」画面の **「6つの観点のスコアはどう出しているか」** を開くと、
観点ごとに構成指標・計算式・向き（大きいほど良いか）が並ぶ。
定義は `src/analysis/scoring.py` の `METRIC_SPECS` にあり、`/api/meta` 経由で
画面に渡している。計算式を文章として別に持たないので、実装とズレない。

### 低い理由をたどる

「詳しく見る・比べる」の **「スコアの内訳」** で、観点をひらくと

1. その観点の点数と、いちばん足を引っ張っている指標の名前と順位
2. 指標ごとの値・402市区町村中の順位・点数
3. その指標の計算式と、**計算に使った統計値（観測年つき）**

まで下りられる。たとえば川口市の住環境28点は、

| 指標 | 値 | 順位 | 点数 |
|---|---:|---:|---:|
| 戸建て中心の街か | 41.5% | 317中 237位 | 26 |
| 図書館の密度 | 0.12館/万人 | 402中 282位 | 30 |

で、戸建比率は一戸建住宅数 112,360戸 ÷ 居住世帯あり住宅数 270,520戸（ともに2023年）
から出ている、というところまで画面上で確認できる。

順位が付かなかった指標には、値が無いのか母数が足りないのかを明記している。
千代田区の土地単価が650万円/㎡なのに点数が付かないのは、**取引が1件しかない**ためで、
それも内訳に出る。

## 既知の制約

事実として押さえておくべき点。

### 更新が止まっている統計

e-Stat側で更新が停止しており、**スコアには使っていない**（画面には観測年つきの参考値として表示）。

| 指標 | 最新年 |
|---|---|
| 刑法犯認知件数 | 2008年 |
| 交通事故発生件数 | 2009年 |

治安・交通安全を数値でスコア化できていないのはこのため。
安全面は「災害リスク」タブの地図で候補地そのものを確認してほしい。

### 更新頻度の違い

年齢別人口（0〜5歳など）は国勢調査由来のため**2020年が最新**で、5年ごとにしか更新されない。
一方で出生数は2023年、学校数は2024年まである。画面では**全ての指標に観測年を併記**している。

### 小規模自治体の density バイアス

人口が少ない町村は「子ども1000人あたりの保育所数」が構造的に高く出る。
一方で医師密度や将来人口では不利になりやすい。ランキングに**人口規模フィルタ**を用意しているので併用する。

例: 美里町（埼玉・人口10,685人）は保育所密度10.1（川口市4.7）だが、
医師密度2.81（川口市15.3）、2050年人口 -20%。

小児科の密度も同じ性質を持つ。人口が減っている地域は分母（子どもの数）が
先に縮むため、施設が増えていなくても密度は上がる。実際、上位には房総半島の
市町（館山市36.5・南房総市35.7・茂原市30.4）が並ぶ。**access としては本当に
恵まれている**が、その裏側は年少人口の減少なので、「将来の見通し」の観点と
必ず併せて見ること。人口10万人以上に絞ると東京23区（江東区22.4・墨田区21.8）が
上位に来る。

### 政令市の扱い

政令指定都市は「市」と「区」の両方がe-Statから返るが、**区の粒度を採用**している
（横浜市青葉区と鶴見区では性格が大きく違うため）。
「特別区部」は23区の合計であって自治体ではないので除外した。

### 診療科目は「標榜」であって診療実態ではない

小児科としているのは、施設が**標榜している診療科目**であって、
実際に小児をどれだけ診ているか・常勤の小児科医が何人いるかではない。
内科と併せて標榜しているクリニックと、小児科専門のクリニックは同じ1施設として数える。
診療時間・休日夜間対応も見ていない。

また元データの診療科目欄が未記載の施設がある。名称に「小児科」を含むのに
科目欄に無いケースが10,983施設中6件あった（例:「わかば小児科クリニック」）。
これらは取りこぼしになる。

施設は**最寄りの市区町村代表点に割り当てて**から数えている。
市区町村の境界そのもので判定しているわけではないので、
境界付近の施設は隣の自治体に寄ることがある（15km圏で集計するため影響は小さい）。

### 利便性は距離であって所要時間ではない

利便性スコアが見ているのは**直線距離**で、鉄道の路線網も快速の停車も反映していない。
同じ距離でも、快速の止まる駅がある街とバスしか無い街は実際の通勤時間が倍以上違う。

市区町村単位で継続的に取れる所要時間の公的オープンデータが無いため、代替を用意できていない。
画面にも「◯◯分」ではなく距離（km）としてそのまま出しているのはこのため。
候補が絞れた段階では、実際の路線と時刻表で確かめてほしい。

同じ理由で、市域の広い市（宮古市・いわき市規模）では代表点1点で市全体を代表させる
無理が出る。代表点は町丁目の中央値なので市街地寄りに来るが、市の端は距離が大きく変わる。

### 世帯年収の試算は目安

借入可能額は年収・返済負担率・金利・年数だけで出している。実際の融資額は勤務先、
勤続年数、既存の借入、団信の可否で変わる。建物＋諸費用も一律の想定値で、
土地の形状や地盤改良、外構は含んでいない。

### データが無い観点は弱点補正を受けない

観点の点数が出せない市区町村は、その観点が加重平均からも弱点判定からも外れる。
たとえば千代田区・中央区は住宅地の土地取引が10件に満たず「手が届きやすさ」の
点数が無いため、他の都心区が価格の低さで受ける減点を受けない。
データが無いことを悪い評価にしない方針の裏返しで、結果として
**取引の少ない自治体がやや有利に出る**。内訳画面では点数が付かなかった理由
（値が無いのか、母数が足りないのか）を明記している。

### その他

- 待機児童数は市区町村単位で継続的に取れる公的統計が無く、保育所密度で代替している
- スコアは公的統計の引用であり、特定の物件や投資判断を推奨するものではない

### 配色

明るい水色が基調。色は `frontend/style.css` の CSS 変数が唯一の定義で、
グラフも JS からそこを読んでいる（ハードコードするとダークモードで追随しないため）。

- 文字・アクセント・警告色は、**実際に載る面に対して WCAG AA（4.5:1）** を満たす値
- 入力欄の枠は面に対して3:1が要るので、パネルの区切り線（装飾）とは別トークン
- 比較用の6色は、色覚特性のある人でも隣同士を見分けられるか（OKLab の色差）と
  描画面とのコントラストを検証した並び。**使い回さず常にこの順**に割り当てる
- スコアの4段階は系列色とは別系統。順位の色と混同させないため
- ダークモードは明度を反転させたのではなく、暗い面用に選び直した値

### グラフ

**単位の違う系列を左右2軸で重ねない。** 2軸にすると交差する位置が縮尺の
取り方だけで決まり、「単価が戸建て価格を追い越した」という無い意味を読ませてしまう。
価格の推移と人口の推移は、それぞれ2枚に分けて並べている。

**同じ指標の市区町村どうしは1枚に重ねる。** 価格・人口の推移は、選んだ
市区町村を重ねて描く（色はチップ・レーダー・比較表と同じ並び）。市区町村ごとに
取れている年が違うので、年の和集合を軸にして無い年は線を継いでいる。

水準の差が大きいと重ねても読めない（渋谷区170万円/㎡ とつくば市3.3万円/㎡ を
実額で並べると安い側が軸の底に張り付く）ので、**「変化（基準年=100）」**に
切り替えられるようにした。基準年は全系列に値がある最も古い年。

世帯年収からの予算計算はフロントエンド側にある（入力のたびに再計算するため）。
金利・年数・上下限といった前提は `config.py` の `BUDGET_MODEL` にまとめてあり、
`/api/meta` 経由でフロントに渡している。定義が二重にならないようにするため。
